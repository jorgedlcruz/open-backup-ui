The largest new asset is the approximately 16.5 MB Noto Sans CJK font. It is an intentional licensed application asset for PDF export, loaded only when the report requires those glyphs. [Font sources and licenses](../../public/fonts/reports/README.md) accompany it.

This is a scoped pattern scan and manual review, not a claim that every possible secret format can be detected.

The source-package file collector selected **848 files**, including **61 regression test files**, with no runtime data, private PDFs, logs or credential files in its output list. These checks inspect the current working tree and package selection; they do not constitute an audit of every historical Git object.

## GitHub Desktop handoff

The Git working tree and index were inspected directly because GitHub Desktop's window capture did not respond. Release preparation did not stage files, commit, push, create a PR, create a tag or publish a release. Do not force-add ignored runtime files.

1. Review the changes on `features/v1.0.1` in GitHub Desktop. Keep the regression tests; generated results and local credentials should not appear in the change list.
2. Commit and publish the branch when the review is complete. Use the first heading of [the PR Markdown](v1.0.1-pull-request.md) as the PR title and the remaining text as its description. Its branch image links become available after pushing.
3. Review CI and merge into `main`. Create `v1.0.1` at the final reviewed source snapshot when ready to release.
4. Convert the portable [release Markdown](v1.0.1.md) to a GitHub release body with the command below. Its tag-based links resolve when the tag and images are published together.

```powershell
node scripts/prepare-release-notes.cjs v1.0.1 jorgedlcruz/open-backup-ui artifacts/github-release-v1.0.1.md
```

The generated body belongs in `artifacts/` and is intentionally ignored. No full live report, saved connection file or raw screenshot directory is needed in the PR or release assets.
