# v1.0.0 screenshot checklist

All 38 feature images are included under `docs/releases/images/v1.0.0/` and embedded in the [release notes](v1.0.0.md). Open the [visual gallery](v1.0.0-gallery.md) for the complete illustrated tour. The table below links each image and retains the current route and suggested framing for replacement captures.

For a GitHub Release, upload the images into the release editor and use its generated URLs. For a blog post, the same feature headings and captions can be reused.

## Capture guide

- Use one theme and viewport for the main tour; reserve the theme comparison for Branding. A 1600 × 1000 desktop viewport and a 390 px phone viewport work well.
- Use a lab or approved demo source. Hide credentials, tokens, personal information, private hostnames, and customer data before publishing. Use representative data, and label any mockup as a mockup.
- Keep breadcrumbs visible. Open the relevant detail, filter, or preview before capture so each image explains one feature.
- Show complete, partial, or learning states honestly. Do not manufacture a forecast or a healthy result for the screenshot.
- Capture existing records and previews. No need to start jobs, resolve alarms, revoke licenses, or save configuration solely for a screenshot.
