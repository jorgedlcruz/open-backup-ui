# v1.2.0: Recovery Center, Embedded Explorers & Multi-VM Recovery

**Base:** `main` · **Head:** `features/v1.2.0`

## Summary

Restore-point actions in v1.0.1 primarily exposed evidence. This change turns them into recovery workflows: choose an exact point, review the destination, submit to VBR, and continue in a session with its logs, browser or recovery map. The new Recovery Center also starts from the recovery goal and brings supported VM, file, application, NAS, object-storage and computer recovery paths into the same workspace.

[Review the eight-image visual guide](v1.2.0-gallery.md). Captures use English and Glass Ocean and show the application with real lab data.

## What's new

- **Recovery Center:** goal-first selection, eligible workload search and type filters, a calendar with separate restore times, automatic latest-point selection, and quick filters for pending, active, actionable, completed and attention-needed recoveries. Breadcrumbs preserve whether a session was opened from Recovery Center or Sessions.
- **VM recovery groups:** Instant VM Recovery and Entire VM restore, with exact point selection and destination review per VM, batch validation, per-VM receipts and links to the resulting native sessions. Other recovery methods remain single-workload flows.
- **Recovery maps and migration:** source backup, VM, host, storage and reported proxy path; animated read/write connectors; native progress and short-term rate charts. Instant Recovery includes migration to production and publication cleanup, including after migration succeeds while publication remains active.
- **Guest-file workspace:** folder tree, breadcrumbs, search and ZIP download. An inline recovery cart/review offers original-location Keep or Overwrite and native credential/path questions. Accepted restores return to browsing with one task-progress area and reload-safe receipts.
- **Embedded Active Directory:** directory tree, object-specific icons, search, attributes, restore/export and a cross-folder recovery cart, with the actions above the grid.
- **Embedded SQL Server:** server/instance/database browsing, scoped instant recovery and restore actions, eligible point-in-time selection, export and publishing, native validation questions, operation tracking and staging-server settings.
- **NAS, object storage and computers:** file/object browsing at the calendar-selected restore point, native restore and copy tasks, live destination-folder browsing, available entire-source/rollback/share-publishing paths, plus eligible Windows physical-computer volume recovery, recovery media and tokens.
- **Global Sessions:** shared filters for session types, platform, state, result and time, with current mount state kept distinct from the completed launch session.
- **Responsive recovery history:** source/principal-scoped catalog and point caches; refresh every 30 minutes while Recovery Center is open; manual Refresh; 200-point history expansion that retains the chosen point and loaded depth.
- **Branding and feedback:** the OB Interlock SVG, Glass Ocean as the new-browser default, theme-consistent controls, source-health/version footer, project version headers/manifest and 200 shuffled loading captions with a conventional spinner.

## Implementation and boundaries

The adapters recheck the selected point, permissions and native inventory before mutation. Recorded request/task handles follow their originating source and account. An interrupted write is reported as unconfirmed rather than automatically replayed. Mass recovery now resolves exact VM IDs from the selected backup's object collection, avoiding a standalone object lookup that returned 404 for valid selections.

Final QA fixes add durable single-start acknowledgements across slow responses and reloads, immutable native-attempt records for starts/batch rows/migrations, a session-status fallback for completed SQL operations, and the kiosk launcher's dependencies in standalone packaging.

The recovery integration targets VBR 13 / `1.3-rev2`. Selected workflows depend on private Web UI APIs, including application Explorer authentication using the saved HTTPS VBR account. Availability depends on server build, point capabilities and permissions. The implementation does not claim desktop-console parity or certification across all platforms.

Bulk recovery is limited to Instant VM Recovery and Entire VM restore: group preflight precedes one native submission per VM in sequence, without atomic rollback of VMs already started. First Class Disk and physical volume recovery remain different paths; the latter requires a connected, verified Windows recovery appliance and an eligible Windows physical-computer backup.

Cloud Director customized placement, YARA scanning, guest-file restore to another VM, NAS/object per-item version selection or all-time browsing, Active Directory production comparison, and an embedded VMware console are excluded. Antivirus scanning is the available secure-restore control. A backup stored in an object repository is not automatically an object-storage source backup. Cache refresh is page-driven; it is not an unattended 30-minute inventory service.

## Validation

- **1,275 automated tests passed**, with no failures or skips.
- Final production build, lint and TypeScript passed; the existing port-3124 preview runs the candidate.
- Production-build browser checks cover reload-safe startup, SQL actions/history, NAS tree/navigation and the inline guest-file cart. Live read-only checks cover the Recovery Center catalog, search, filters and point selection.
- Runtime dependency audit reports **zero advisories**. The full audit reports seven moderate findings in development lint dependencies; no high or critical findings.
- Version headers/manifest, release links and packaging are checked as detailed in the [validation report](v1.2.0-validation.md).

Local validation used Windows/Node 24. Clean Node 20/22 CI and disposable-lab acceptance of real recovery writes remain before release. API fixtures and browse-only checks do not establish successful restoration on every platform.

## Upgrade and review

Preserve persistent `data/` and the encryption key, install with `npm ci`, and build/start through the existing deployment. Recovery caches rebuild on restart; carts and some file-operation receipts are browser-tab scoped. Existing appearance preferences are preserved. Review [deployment and access controls](../deployment.md) before exposing management actions outside a trusted interface.
